<Section label="The problem" title="Consistency had to survive implementation">
  Timeflow needed one product language across a daily review flow, manager views, approvals, integrations and privacy
  controls. A shared Figma file was not enough. The same hierarchy and state meanings had to survive implementation and
  repeated use across different workflows.
</Section>

<Principle label="Principle" text="Design and code are two interfaces to the same product language." />

<Section label="System architecture" title="One decision, reused through the stack">
  The architecture connected visual foundations, Figma frames, repeated interface patterns and the rendered React
  product. The value came from keeping decisions stable as the environment changed.
</Section>

<Section label="Foundations" title="Name the role each visual decision plays">
  The foundations were defined by purpose. Parchment softened an administrative workflow. Teal carried time and
  completion. Orange was reserved for attention. Neutral structure kept manager views calm.

<Section label="Where it got complicated" title="Attention colour stopped communicating attention">
  The existing Timeflow case records a screenshot audit of the manager view. Six orange elements were competing at the
  same time, so the colour no longer identified the items that needed action.
</Section>

<Stats items={[{ value: "6", label: "Simultaneous orange elements found in the manager view" }]} />

<Cards columns={1}>
  <Card label="Visual audit" title="Reduce competition, preserve meaning">
    The audit reduced orange to three sanctioned uses. Other emphasis moved to neutral treatments so warning and attention states could carry a distinct role again.

    This was a system decision, not a local colour adjustment. The same rule had to remain understandable across summaries, heatmap states, badges and attention cards.

  </Card>
</Cards>

<Section label="Behaviour" title="States belong to the system too">
  The product evidence shows a repeated state vocabulary across daily work, manager oversight and approvals. Colour
  supports the state, while labels, values, legends and placement carry meaning in context.
</Section>

<Section label="Outcome" title="A shared product language across design and implementation">
  Timeflow moved from Figma frames to a deployed working MVP using React, TypeScript, Tailwind and shadcn. The same product decisions appear across employee review, manager oversight, approvals, integrations and privacy settings.

The result is evidenced through repeated behaviour in the product, not through an isolated component inventory.

</Section>
