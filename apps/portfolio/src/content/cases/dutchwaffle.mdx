<Section label="The problem" title="At B1, the gap is nuance, not vocabulary">
  Most language apps stop at words. At B1 a learner can already order coffee and fill in a form; what they can't yet do
  is hedge, disagree politely or soften an opinion at work. DutchWaffle is built around those phrases. Each one comes
  with its pronunciation, its meaning, a note on when to use it, and an example sentence in context.
</Section>

<Principle text="Teach the phrase, not the word: knowing when to say it matters as much as what it means." />

<Section label="Key decision" title="Stack or flip">
  The prototype tested two flashcard metaphors side by side. A stack shows the next cards behind the current one and
  keeps momentum. A flip hides the meaning until you turn the card, which makes you try to recall it first. For phrases
  whose whole point is when to use them, recall mattered more than speed, so flip won for v1.
</Section>

  Alongside the app sits a searchable bank of 38 idioms and expressions across six themes, from work and career to media
  and news, ordered from B1 to B2. The phrases live in one data file, so a new theme or expression updates search,
  filters and counts without touching the interface.
</Section>

<Section label="Design system" title="Dark, calm, one accent and one caramel">
  A charcoal-green base, one teal accent for progress and actions, and a warm caramel borrowed from the stroopwafel for
  the character and moments of praise. Urbanist with named type styles, an 8-point spacing scale, and no gradients
  outside a single lesson card. Every value lives in one token file that components read through `useTheme()`.
</Section>

<Section label="Handoff" title="A spec written for an AI agent to build from">

  against it line by line.

<Section label="Where it got complicated" title="The bugs only showed up on real devices" />

<Cards columns={3}>
  <Card title="A flip that mirrored the text">
    The flip relied on `backfaceVisibility` to hide the face turned away. On Android and the web it didn't, and the back
    of the card showed through mirrored. **The fix switches each face's opacity at exactly 90°**, so only one face can
    ever be visible.
  </Card>
  <Card title="A mascot that vanished on the web">
    dhr. Waffle is an SVG with gradients. With several on one screen, they shared gradient IDs and the browser rendered
    some of them transparent. **Each instance now gets its own IDs.**
  </Card>
  <Card title="The version chain">
    To test on a real phone in Expo Go, the project had to match the SDK that Expo Go ships with, and then every native
    module, from Reanimated to the SVG renderer, had to match that SDK's bundled versions. **Device testing set the
    stack, not the other way round.**
  </Card>
</Cards>

<Section label="Learnings" title="What this taught me" />

<Cards columns={3}>
  <Card title="A handoff is a prompt">
    The more precisely the spec described states and acceptance criteria, the less the build had to guess. Writing it
    was design work, not documentation.
  </Card>
  <Card title="Review is the job">
    AI wrote much of the code. My part was deciding what it should do, then checking that it did, screen by screen.
  </Card>
  <Card title="Test on every platform">
    The same React Native code rendered differently on iOS, Android and the web. What one platform hid, another showed,
    so each one gets checked before a change counts as done.
  </Card>
</Cards>
